# 开发路线图与验收标准｜拾己 · LIFE

## 1. 开发策略

采用垂直切片：先完成一段从进入游戏到保存经历的真实可玩流程，再加入阶段回顾。不要先铺开所有地图、NPC 和 AI 能力。

## 2. 里程碑

### M0：项目骨架
- 检查现有仓库、技术栈和运行方式。
- 建立路由、全局样式、基础布局。
- 建立文档、代码规范和测试脚本。
- 验收：项目可安装、启动、构建。

**状态：已完成（2026-11-20）**

- 技术栈：Vite 8 + React 19 + TypeScript 7 + Tailwind CSS 4 + React Router 7 + Zustand 5 + Vitest 5（oxlint 做静态检查）。
- 已建立：设计令牌（`src/index.css`）、路由表（`src/app/App.tsx`）、开始页、七个占位页、localStorage 存档探测（`src/services/storage.ts`）、领域类型（`src/types/game.ts`）。
- 已验证：`npm run typecheck`、`npm run lint`、`npm test`（6 项）、`npm run build` 全部通过；桌面与 390px 移动视口渲染正常。
- 尚未建立：事件 JSON schema、游戏引擎 reducer、AI 适配层（分别属于 M2、M4）。

### M1：首章可玩
- 开场剧情。
- 角色创建。
- 城市首页。
- 中央广场、家、校园、公园入口。
- 微光首次登场和基础对话。
- 首次探索。
- 本地存档。
- 验收：新玩家完整走完第一章，刷新可恢复。

**状态：已完成（2026-11-20）**

- 开场五幕（雨、房间、信、地图、门），第三幕有一次语气选择，可整体跳过。
- 角色创建：昵称、四款 SVG 形象、人生状态与探索问题（均可跳过）。
- 城市首页：七个热区（四个可进入，三个显示建造中），状态栏显示天数、时段与精力。
- 微光首次见面为脚本对话，三选一开场后汇合；认识后可再次呼唤，只做简短回应，不做任何分析。
- 四个区域各 3 个行动，行动有精力变化与时段推进，结果文案只描述发生的事。
- 第 1 章完成卡会出现一次，并自动滚入视野，提供「打开人生档案」（占位）入口。
- 存档：`src/game/saveSchema.ts`（Zod 校验、版本号 v1）+ `src/services/saveService.ts`（损坏保护）；刷新可恢复。
- 路由改为 HashRouter：实测 Qoder Sites 静态托管对 `/archive`、`/city` 返回 404，没有 SPA 回退。
- 已验证：`typecheck`、`lint`、`test`（14 项）、`build` 通过；无头 Chrome 完整跑通「首页 → 开场 → 建角 → 城市 → 公园 → 行动 → 返回 → 通关卡 → 刷新恢复」。
- 未包含：事件系统与经历记录（M2）、阶段回顾（M3）。

### M2：事件和经历
- 事件 JSON schema。
- 事件剧情页面。
- 选择、结果、有限分支。
- 经历记录和授权设置。
- 验收：不同选择产生正确结果；经历记录可查、可删除。

**状态：已完成（2026-11-20）**

- 事件契约：`src/game/eventSchema.ts`（Zod，2–4 个选项、结果文案长度上限、效果字段限定）。全部内容在 `src/data/events.ts` 加载时校验，写错会在构建阶段暴露。
- 首批 5 个事件：校园《那个没有发出的消息》《走廊里的三个人》、家《永远在准备开始》、广场《如果没有人评价你》、公园《被落下的书》。四个选择只是不同，没有对错提示。
- 事件页：叙事 → 选择 → 结果；效果只经 store 执行（精力、时段、剧情标记）；带重复提交保护。
- 经历：选择后写入一条记录（标题与结果快照、发生时游戏内时间）；授权默认关闭，由设置页开关决定新经历的默认值，结果页与档案页可逐条修改。
- 可选理由：家中事件提供「当时是怎么想的」输入，可整段跳过；空白存 `null`，绝不代写。
- 档案页：经历列表、逐条授权、二次确认后软删除；认知卡片区留空待 M3。
- 设置页：默认授权开关（只影响新经历）、删除全部数据（二次确认，失败不假装成功）。
- 经历查询集中在 `src/services/experienceService.ts`：`getVisibleExperiences` 与 `getEligibleExperiences`，M3 只允许用后者。
- 存档升到 v2：新增 `experiences`、`seenEventIds`、`settings`；`migrateSave` 实现 v1 → v2 补默认值，旧档进度不丢（有测试覆盖）。
- 修复 M1 遗留缺陷：`localStorage.getItem`/`removeItem` 抛 `SecurityError` 时不再白屏，读取返回 `null`、清除返回 `false`，页面显示写盘提示（有测试覆盖）。
- 事件完成改为**原子提交**：`completeEvent` 一次构造并写盘（精力、时段、标记、已读、经历），写盘失败不会留下「已读但无经历」的半完成存档；重复调用幂等。
- 首屏「继续旅程」改用轻量有效存档判断（`savePeek`）：检查版本、角色、章节、场景、天数、时段、精力、经历、设置等必需字段；损坏或结构不完整的存档不再提供继续入口，同时不把校验库带入首包。
- 若首屏判断通过、完整校验仍失败（例如某条经历内部结构损坏），城市页会带提示回到首页——「上一份存档读不出来，可能需要重新开始」，并禁用继续入口，避免「点了又弹回」的循环。
- 结果直播区（`aria-live`）在事件页常驻，选择后才填充内容，保证首次结果被读屏播报。
- 存档版本判断收紧：只迁移明确的 v1；0、负数、小数与高于当前的版本一律拒绝，且不覆盖原始数据。
- 事件 schema 增加选项 id 唯一性校验。
- 体积：路由级代码分割 + 依赖分包，首屏从 127 KB gzip 降到约 96 KB，校验库随进入游戏时加载。
- 已验证：`typecheck`、`lint`、41 项测试、`build` 通过；无头 Chrome 实测「事件 → 选择 → 理由 → 授权 → 档案 → 设置 → 390px」。
- 未包含：真实 AI 分析、阶段回顾与认知确认（M3）；多节点剧情图（当前一个选择即为一处汇合点）。

### M3：阶段回顾（先 mock）
- 阈值判断。
- 回顾邀请、接受、稍后、拒绝。
- 经历回顾时间线。
- mock 观察结果。
- 确认、修改、拒绝观察。
- 认知档案。
- 验收：完整跑通经历 → 候选观察 → 玩家确认 → 认知卡片。

### M4：接入真实 AI
- 服务端模型适配层。
- Prompt 版本管理。
- JSON schema 校验。
- evidence ID 校验。
- 超时、失败和无观察降级。
- 验收：AI 不可用时游戏仍可玩；AI 不得越权写入正式档案。

### M5：现实行动与阶段总结
- 现实行动创建和状态。
- 行动复盘。
- 人生档案阶段总结。
- 验收：玩家可将认知转成行动，并记录结果。

## 4. MVP 验收清单

### 游戏
- [ ] 新玩家可完成首章。
- [ ] 角色创建字段可选且可跳过。
- [ ] 城市区域入口可用。
- [ ] 事件选择和分支正确。
- [ ] 刷新后恢复存档。
- [ ] AI 服务失败不阻断游戏。

### 经历与回顾
- [ ] 有效经历被正确保存。
- [ ] 撤回授权的经历不会进入后续分析。
- [ ] 达到阈值才触发邀请。
- [ ] 邀请支持接受、稍后、拒绝。
- [ ] 拒绝后不会立即反复邀请。
- [ ] 展示观察对应的经历证据。
- [ ] 证据不足时不生成观察。
- [ ] 玩家确认前不写入正式认知档案。
- [ ] 玩家可修改、拒绝和删除认知卡片。

### 隐私与安全
- [ ] 私人日记默认不用于 AI 分析。
- [ ] AI Key 仅在服务端。
- [ ] API 按用户隔离数据。
- [ ] LLM 输出经过 schema 校验。
- [ ] 不存在跨用户读取。
- [ ] 删除/撤回授权后，后续分析不再使用相关内容。

### 工程
- [ ] typecheck 通过。
- [ ] lint 通过（若配置）。
- [ ] 单元测试通过。
- [ ] build 通过。
- [ ] README 含启动说明和环境变量说明。
- [ ] 数据库迁移可从空库执行（接入数据库后）。

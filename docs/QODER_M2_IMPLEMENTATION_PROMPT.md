## 任务正文

### 一、背景与目标

M1「首章可玩」及两轮修复已经完成。当前提交为 `0eb2d79`，技术栈与目录保持现状。

M2 的目标是把当前“场景里点一个行动、立即出现一段结果”的静态体验，升级为真正的事件闭环：

**场景入口 → 事件剧情 → 2–4 个自主选择 → 有限分支与汇合 → 客观结果 → 保存经历 → 在人生档案查看、撤回分析授权或删除。**

依据：

- `docs/ROADMAP_AND_ACCEPTANCE.md` M2：事件 JSON schema、事件剧情页面、选择/结果/有限分支、经历记录和授权设置。
- `docs/PRODUCT_PRD.md` F07、F08：事件结构、可选理由、经历授权、查看/删除/撤回。
- `docs/TECHNICAL_PRD.md`：游戏引擎、经历服务、UI 与 localStorage 分层。

### 三、先处理一个 M1 遗留缺陷

Qoder 对 M1改动2 的浏览器复核发现：

- 仅让 `Storage.setItem()` 抛错时，游戏可继续且写盘提示正常。
- 但让 `Storage.getItem()` 也抛出 `SecurityError` 时，页面会在启动阶段白屏。
- 根因：`src/services/storage.ts` 的 `readRawSave()` 没有捕获 `getItem()` 异常；`src/services/saveService.ts` 又在 `try` 外调用它。`clearSave()` 的 `removeItem()` 也没有异常保护。

请先用失败测试复现，再做最小修复：

- 读取不可用时返回 `null`；写入不可用时返回 `false`。
- 清除失败不得伪装成成功；不要因此覆盖或损坏原始数据。
- 完全禁用存储时应用仍能进入首页，开始游戏后出现现有的 `PersistenceNotice`，而不是白屏。
- 保持现有写盘失败提示和“内存中可继续玩”的行为，不引入新的状态系统。

这是恢复既有产品承诺的缺陷修复，不扩展功能。

### 四、范围与非目标

#### 本轮必须完成

1. 事件数据的 Zod schema 与加载校验。
2. 确定性事件引擎：节点推进、合法选项、有限分支、汇合、结果与数值效果。
3. 至少 1 个完整事件垂直切片，再扩展到 5 个短事件；内容扩展不得另起第二套引擎。
4. 事件剧情页与场景入口，支持鼠标和纯键盘。
5. 经历持久化、人生档案经历列表、删除、单条分析授权撤回/恢复。
6. 设置页提供“新经历默认允许用于分析”的明确开关，默认关闭。
7. v1 → v2 存档迁移，保留玩家已有角色、进度、标记与访问记录。
8. 关键业务测试、页面流程测试和构建验证。

#### 明确不做

- 不做 M3 阶段回顾、阈值邀请、候选观察或认知卡片。
- 不接真实 AI，不新增 AI 网络请求，不让 AI 写游戏状态。
- 不做账号、数据库、后端、导出、日记或现实行动。
- 不做无限分支、复杂条件脚本、自定义事件编辑器或完整游戏引擎。
- 不新增 UI 库、游戏引擎或外部图片素材，不重画地图，不升级依赖。
- 不把普通场景行动全部强行改造成需要阅读的长剧情；保留轻量行动与完整事件两种入口。

### 五、推荐实施顺序（小步垂直切片）

#### 第 1 步：一个事件的规则与测试

先只实现一个短事件及其测试，不做五个事件的大批量文案。

建议边界：

- `src/game/events/`：事件 schema、类型与确定性引擎，不引用 React 或 store。
- `src/data/events/`：静态事件数据；加载时通过 schema 校验。
- `src/services/experienceService.ts`：经历创建、查询、授权过滤与删除规则，不直接操作 UI。
- 页面只负责展示与调用 action，不自行计算精力、时间或分支结果。

事件至少表达：起始节点、叙事段落、2–4 个选项、选项后续节点、汇合节点、结束结果、经验类型与效果。有限分支后必须能汇合，不做指数级剧情树。

#### 第 2 步：事件页与场景入口

- 增加 `#/event/:eventId` 或等价哈希路由。
- 在现有区域中放入清晰的事件入口；不要替换全部轻量行动。
- 事件页展示场景、剧情、当前可选选项与客观结果。
- 未知事件 ID、非法节点和坏数据有安全返回或明确错误状态，不白屏。
- 刷新只要求恢复已提交的进度；可不保存半途选择，但不得重复扣除精力或重复生成经历。若选择保存半途状态，也必须有恢复测试。

#### 第 3 步：原子完成事件并写入经历

推荐在完成节点一次性提交“游戏效果 + 经历记录”，避免多步 action 造成半完成状态。

必须保证：

- 同一事件完成动作最多应用一次效果、生成一条经历。
- 精力仍钳制在 0–100；时间规则复用现有引擎规则。
- 结果只描述客观发生的事，不根据一次选择推断人格。
- 玩家理由/感受为可选，跳过可继续；未填写时保存 `null`，不得代写。

#### 第 4 步：人生档案与授权设置

将人生档案占位页替换为“经历”视图；认知卡片仍可保留明确的 M3 占位，不提前实现。

玩家可以：

- 查看事件发生场景、类型、所选内容、客观结果、游戏内时间及创建时间。
- 删除单条经历，删除前看到清晰确认；取消不改变数据。
- 撤回或恢复该经历的分析授权。
- 在设置页修改“新经历默认允许用于分析”；默认关闭，只影响之后创建的经历，不批量改写旧记录。

M2 没有 AI 调用，但经历服务必须提供“仅返回有效且已授权经历”的查询入口，供 M3 使用。撤回或删除后，该记录立即不再出现在此查询结果中。

#### 第 5 步：扩展到五个短事件

在第一条垂直切片测试通过后，再用同一数据格式扩展至 5 个短事件。优先覆盖家、校园、公园；可使用 `GAMEPLAY_AND_STORY.md` 的三个示例主题，其余保持短而克制。

至少包含：

- 一个有限分支后汇合的事件。
- 一个人际类事件与一个行动类事件。
- 一个提供可选理由/感受输入、且可跳过的事件。
- 不把“主动”“立刻行动”“外向”写成唯一正确或更优选项。

### 六、数据契约要求

具体字段命名可按现有代码风格调整，但语义不能缺失。

#### 事件

- 稳定的 `eventId`、标题、章节、场景、经历类型、起始节点。
- 节点 ID 唯一，跳转目标存在，起始节点可达，结束节点可达。
- 每个选择有稳定 `choiceId`、显示文本、后续节点与可选效果。
- 结局文本及经验记录所需信息必须来自事件定义，不由 UI 临时编造。
- schema 拒绝缺失字段、非法枚举、空选项、超过 4 个选项、重复 ID 与悬空跳转。

#### 经历

至少记录：

- 唯一 `id`。
- `eventId`、`sceneId`、`experienceType`。
- 玩家实际走过的 `choiceIds`，以及用于展示的客观选择/结果摘要。
- 可选 `playerReason` / `playerFeeling`，未填写为 `null`。
- `analysisConsent` 布尔值。
- `createdAt`，以及发生时 `gameDay` / `timeSlot`。
- 若采用软删除，必须有一致的 `deletedAt` 过滤；若采用物理删除，必须确认后从存档移除。M2 只选一种，不混用两套语义。

唯一 ID 使用浏览器现有能力（如 `crypto.randomUUID()`）并提供测试可控的生成方式，不引入新依赖。

### 七、v1 → v2 存档与隐私红线

当前 `SAVE_VERSION = 1`，且 `saveSchema.version` 是 `z.literal(1)`。M2 新增经历与默认授权设置时必须升版并真正迁移，不能把旧档判为无存档。

建议 v2 新增：

- `experiences: []`
- `settings.analysisConsentDefault: false`

迁移要求：

1. 逐级识别 v1，补齐 v2 默认值；保留 `profile/chapter/currentScene/gameDay/timeSlot/energy/flags/visitedScenes/prologueDone/createdAt`。
2. 迁移成功后才能写入新格式；迁移或校验失败不得覆盖原始 localStorage 字符串。
3. 缺失、非数字或高于当前版本的 version 仍按不支持处理，不猜测迁移。
4. 可暂时保留现有存储 key 以减少迁移风险；若更改 key，必须读取旧 key、验证迁移写入成功，并保留失败恢复路径。
5. 所有持久状态仍通过 store action 与服务层写入，页面不得直接访问 localStorage。
6. 写盘失败继续显示 `PersistenceNotice`，不能因新增经历而静默丢失。

隐私与产品红线：

- 新经历的分析授权默认关闭，不用含糊文案替玩家同意。
- 关闭默认授权不删除已有经历；删除经历不影响其他游戏进度。
- 普通事件完成后不立即做任何 AI 分析或人格反馈。
- 不生成“你是……的人”“你缺乏……”“焦虑型/内向型”等标签或诊断。
- 不用羞耻、恐惧、惩罚、损失提示逼迫授权或填写理由。

### 八、测试要求（先写关键失败测试）

至少覆盖：

1. 合法事件通过 schema；重复 ID、悬空节点、非法选项数量被拒绝。
2. 两个不同选择产生各自正确后续与结果，分支能汇合。
3. 精力与时间效果正确，精力仍不越界。
4. 完成事件只写一条经历；重复提交/返回结果页/刷新不重复扣精力或写经历。
5. 理由为空可完成，填写后才保存玩家原文。
6. v1 存档迁移后旧进度完整，新增字段使用默认值；迁移失败不覆盖原始数据。
7. 损坏 JSON、schema 失败、未知高版本、存储读写异常均不白屏、不覆盖原始数据。
8. 默认授权为 false；单条撤回后不再进入授权查询，恢复后才重新进入。
9. 删除确认与取消；删除后授权查询和人生档案都不再显示该条。
10. 页面流程：场景 → 事件 → 选择 → 结果 → 档案；键盘可完成，390px 无横向溢出。

不要为了通过测试修改正确断言，不写空断言或只测快照而不验证行为。

### 九、浏览器验收清单

桌面与 390px 手机视口都走一遍：

1. 用 v1 原始存档启动，角色、昵称、精力、标记与访问区域保留；新经历列表为空，默认分析授权关闭。
2. 进入有事件的场景，打开事件，分别选择两个不同选项，结果与分支正确。
3. 完成事件后只增加一条经历，精力/时段只变化一次；刷新后结果与经历保留。
4. 可选理由不填写也能完成；填写时档案只显示玩家实际写下的内容。
5. 人生档案能查看、删除、撤回和恢复单条经历授权；取消删除不改变记录。
6. 设置页默认开关只影响新经历，不追溯修改旧经历。
7. 禁用存储读写时不白屏；仅写入失败时提示仍存在且游戏可继续。
8. 纯键盘可完成事件与档案操作；焦点可见，动态结果有适当播报。
9. `/#/event/<有效ID>`、`/#/archive`、`/#/settings` 可直接打开；无效 ID 不白屏。
10. 控制台无未处理异常，390px 无横向溢出或文字截断。

# Qoder 使用说明

> 写给评委：这个项目的主要开发工作使用 **Qoder** 完成，构建与部署使用 **Qoder Sites**。
> 本文说明 Qoder 用在哪里、怎么用，以及哪些判断是由人做出的。

## 一句话

方向、内容与审美由人决定；页面、组件、动效、状态、测试与修复的编码由 Qoder 完成；构建与部署使用 Qoder Sites。

## Qoder 承担的工作

1. **工程搭建与重构**：React 19 + TypeScript + Vite 工程、目录结构、路由与懒加载。
2. **页面与组件实现**：开始、序章、建角、城市、场景、事件、阶段回顾、人生档案、日记、现实行动、设置共 11 个路由。
3. **动效系统**：GSAP 开屏、章节幕布、页面入场、事件结果时间线、打字机与减少动态效果降级。
4. **状态与存档**：Zustand 游戏状态、Zod 存档校验、授权与撤回、软删除与恢复。
5. **测试**：Vitest 单元/组件测试（51 项）与 Playwright 端到端验收（旅程、可访问性、视觉、性能、部署）。
6. **问题修复**：存档损坏降级、路由深链接、重复结算、移动端移除后的布局整理、设计令牌统一等。
7. **设计规格落地**：把 `specs/gta-ui/` 下的视觉与动效合同、`GTA_G_UI_SPEC.md` 的组件描述落成代码。

## 使用方式

- **Agent 模式**：给出目标（例如“把设置页改成权限登记纸的版式”），Qoder 读取代码库、定位相关文件、跨文件修改，不需要人逐文件指路。
- **代码库理解**：在 `features/`、`motion/`、`store/`、`domain/` 之间联动修改时，Qoder 能保持状态、类型与测试同步。
- **自检闭环**：每次改动后运行 `npm run check`（类型检查 → Lint → 测试 → 构建），失败项回到 Qoder 继续修，直到全绿。
- **部署**：仓库连接到 **Qoder Sites**，构建产物 `dist/` 直接发布为公网链接；`public/_redirects` 提供单页应用回退。

## 人负责的部分

- **决定做什么**：从城市生活、阶段回顾、私人日记到现实行动的闭环。
- **审美方向**：GTA 式城市拼贴、米白新闻纸、粗描边、硬阴影、半调网点；后期加入纸张纤维、折角与套印错位，去掉“AI 模板感”。
- **产品原则**：不诊断、不评判、不贴标签；选择前不透露结果；所有经历由玩家授权后才进入回顾。
- **验收与取舍**：逐页截图比对、可访问性检查、确定只保留 PC 端并移除移动端布局。

## 为什么适合用 Qoder

- 项目页面多、状态与测试耦合紧，Agent 模式能一次处理多个文件并保持类型一致。
- 设计规格是可读的合同（YAML + Markdown），Qoder 能直接读取并落地，减少“设计稿到代码”的损耗。
- Qoder Sites 让静态构建直接上线，评委点开即可体验，不需要登录或后端。

## 任务正文

### 背景

M3（阶段回顾）已完成并提交。这是产品的核心差异点：玩家先生活、再回顾、只把本人确认的内容记下来。

开始前：`git pull`，阅读 `AGENTS.md`、`README.md`、`docs/ROADMAP_AND_ACCEPTANCE.md` 的 M3 小节、`docs/AI_REFLECTION_SYSTEM.md` 第 2、3、5、9 节，以及 `docs/DECISIONS_AND_OPEN_QUESTIONS.md` 里关于阈值与授权优先的三条记录。

存档已升级到 **v3**（新增 `reflections`、`candidateInsights`、`insights`、经历的 `choiceTags` 与回顾设置），迁移链是 v1 → v2 → v3，这是本轮审查重点。

### 一、构建验证（真实执行，粘贴原始输出）

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

### 二、功能验收

准备：完成 3 个事件（校园两个、家一个），或在控制台构造一份含 3 条已授权经历的 v3 存档。

1. 回到城市 → 出现微光的邀请卡「最近我们一起经历了不少事…」。
2. 点「稍后」→ 卡片消失；存档里该会话为 `postponed`，`cooldownUntilGameDay` 为次日，冷却期内不再出现邀请。
3. 点「这次不聊」→ 同样是冷却，不出现任何惩罚或催促文案。
4. 点「现在聊聊」→ 回顾页先显示授权列表。**默认全部未授权**（新经历默认关闭授权），需要玩家逐条点开。
5. 授权不足 3 条或不足 2 类时，「开始回顾」应为禁用状态，并显示当前计数。
6. 授权足够 → 开始回顾 → 显示「这些事」时间线与「微光注意到」的候选观察。每条必须包含：分类、标题、事实描述、猜测、`这只是猜测` 标签、**依据列表**（事件名与选择）、一个开放问题。
7. 点「是的，像我」→ 该候选变为已确认；点「不太像」→ 不进档案且没有任何负面提示；点「改一下」→ 可改写文字后「保存为我的想法」。
8. 所有候选处理完后 →「结束这次回顾」→ 收尾页 →「看看人生档案」→ 卡片出现在「关于自己的认识」下，按五类分组，显示依据条数与确认时间。
9. 在档案里删除认知卡片（二次确认）。
10. 设置页关闭「允许微光主动邀请回顾」→ 城市页不再出现邀请；已有卡片不受影响。
11. **旧档迁移**：用 v2 存档启动（可参考 `src/stores/useGameStore.test.ts` 中的样例），进度、经历、授权状态保留，经历自动补 `choiceTags: []`，设置补上阈值与邀请开关默认值。
12. 手机 390px 走完一次回顾；直接访问 `/#/reflection` 时若没有进行中的会话，应回到城市而不是白屏。

### 三、代码审查（只报告，不擅自改）

- `src/game/reflection.ts`：触发条件是否只依赖「可见经历」与设置；冷却与进行中会话的判断是否可靠。
- `src/game/insightRules.ts`：是否可能使用未授权或已删除的经历；每条候选是否都有证据 id；是否可能出现评价性、诊断性措辞。
- `src/stores/useGameStore.ts`：`generateCandidates` 只能读取已授权经历；`confirmCandidate` 是唯一写入正式认知的入口；重复生成不会复制候选。
- `src/pages/ReflectionPage.tsx`：确认前的候选不能出现在档案；否认不留痕；完成回顾后不会因为「会话结束」被错误重定向。
- `src/services/saveService.ts`：v1 → v2 → v3 链式迁移是否只补默认值；未知或非法版本是否拒绝且不覆盖原始数据。
- 文案红线：不能出现「你是……的人」「你缺乏……」「内向型 / 焦虑型」等标签；不能制造羞耻或催促。
- 可访问性：授权开关 `role="switch"`、候选操作可用键盘完成、动态区有播报。

### 四、部署与部署后验证

1. 首页可打开，`/#/reflection` 不白屏（无会话时回到城市）。
2. 完成 3 个事件后，城市能出现邀请。
3. 走完一次回顾，刷新后认知卡片仍在。
4. 手机视口可完成整个回顾。

### 明确不做

- 不接入真实 AI，不新增网络请求。
- 不改变阈值、文案口径与「确认后才入档」的流程。
- 不重构目录、不升级依赖、不引入新库。
- 不为了让测试通过而修改断言。
- 不提交密钥或真实个人信息。

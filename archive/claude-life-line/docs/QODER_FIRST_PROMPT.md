# Qoder 第一次任务提示词

请先完整阅读项目根目录 `AGENTS.md`、`README.md`，以及 `docs/` 下的项目上下文、产品 PRD、技术 PRD、玩法剧情、AI 人生回响系统、路线图和决策记录。

当前任务不是立即开发完整游戏，而是进行一次项目理解与实施规划。

请按以下步骤执行：

1. 检查当前工作区文件、目录、Git 状态、已有代码、依赖和运行脚本。
2. 对照文档，说明当前仓库与产品需求之间的差距。
3. 用自己的话总结《拾己 LIFE》的定位、核心用户流程、阶段反馈 B 方案和不可破坏的产品原则。
4. 检查推荐技术栈是否适合当前仓库；若仓库已有技术栈，不要擅自重建。
5. 给出建议的项目目录结构。
6. 将整个 MVP 拆成可独立验收的开发任务，按依赖关系排序。
7. 指出文档中的待确认事项和潜在风险。
8. 给出第一阶段最小垂直切片的实施计划、拟修改文件和验收命令。

约束：
- 本轮只分析和规划，不修改业务代码，不安装依赖，不执行破坏性命令。
- 不得擅自改变产品定位和已确认决策。
- 不得把 AI 观察做成人格诊断。
- 不得让 LLM 直接修改游戏状态或正式认知档案。
- 如果文档有不一致或缺少信息，列出问题，不要自行编造决定。

最终输出：
A. 项目理解摘要  
B. 当前仓库检查结果  
C. 技术方案评估  
D. MVP 开发任务拆解  
E. 风险和待确认事项  
F. 第一阶段开发计划与验收标准
